# AI Art Agent 后续需求

更新时间：2026-07-30

## 目标

在当前文字生图 MVP 的基础上，降低中国用户理解和使用 ComfyUI、模型及工作流的门槛。

## P1：优先实施

### 1. 选择 ComfyUI 目录后自动启动

- 用户选择本机 ComfyUI 目录并验证通过后，可直接点击“启动 ComfyUI”。
- 应自动识别常见 Python 环境和启动方式，并显示启动中、已连接、启动失败等状态。
- 软件退出时只关闭由本软件启动的进程，不影响用户手动启动的 ComfyUI。
- 启动失败时展示中文原因，同时保留可展开的原始日志。

### 2. ComfyUI 错误同步与中文解释

- 同步连接失败、节点缺失、模型缺失、显存不足、参数错误和执行失败等错误。
- 默认展示易懂的中文说明、可能原因和建议操作。
- 保留原始英文错误、节点名称、任务编号和完整日志，便于排查和反馈。
- 中文解释必须基于明确的错误规则或结构化错误信息；无法识别时不得编造原因。

### 3. 已搭建工作流的导入与本地导出

- 支持导入 ComfyUI API 工作流 JSON，并转换成软件中的可用模板。
- 支持将当前配置导出为本地工作流文件。
- 导入时检查所需模型、节点和关键参数，并列出缺失项。
- 第一阶段只处理“工作流导入导出”；自定义节点代码的自动安装单独设计权限、安全和版本管理。

## P2：模型体验

### 4. 模型预览与下载

- 提供模型卡片、预览图、类型、基础模型、文件大小、来源和许可证信息。
- 支持下载进度、暂停/继续、失败重试、磁盘空间检查和文件哈希校验。
- 下载前明确保存位置和使用许可；下载完成后刷新 ComfyUI 模型列表。
- 第一阶段接入一个明确、可追溯的模型来源，后续再扩展多个来源。

### 5. 模型用途的中文说明

- 模型导入或扫描后显示中文用途、适合画面、触发词、推荐参数和限制。
- 优先读取模型来源页、模型卡或本地元数据；文件名只作为辅助信息。
- 无可靠元数据时标记为“信息不足”，允许用户手动补充，不能仅凭名称生成确定性结论。
- 支持按用途筛选，例如写实、动漫、人物、风景、风格和放大模型。

## 建议实施顺序

1. 完成当前 Windows 安装包和启动验证。
2. 打通“选择目录 → 自动启动 ComfyUI → 状态与错误同步”。
3. 增加工作流导入、依赖检查和本地导出。
4. 建立模型元数据索引和中文说明。
5. 接入带许可证确认、断点续传和校验的模型下载。

## 验收原则

- 普通用户不需要阅读节点 JSON 或英文堆栈即可完成主要操作。
- 所有中文解释都能展开查看原始信息。
- 下载、安装自定义节点或启动外部进程前均明确目标、来源和影响范围。
- 不替用户静默修改已有 ComfyUI 环境。
