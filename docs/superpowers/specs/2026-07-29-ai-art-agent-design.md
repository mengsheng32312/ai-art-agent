# AI Art Agent 首版设计

## 目标

构建一个 Windows 桌面应用，让用户无需操作 ComfyUI 节点，通过友好的表单完成文生图、查看进度和管理生成结果。

## 首版范围

- 首次启动配置 ComfyUI。
- 支持选择本地 ComfyUI 安装目录。
- 支持填写远程 ComfyUI API 地址。
- 检测 ComfyUI 连接状态。
- 读取可用 checkpoint 列表。
- 提交文生图任务。
- 展示任务进度、错误和生成结果。
- 保存本地生成历史。
- 提供内置基础文生图工作流。

首版不包含模型下载、LoRA 管理、视频生成、训练和游戏资源导出。

## 架构

### 桌面层

Tauri 负责应用窗口、系统目录选择、本地进程启动和桌面打包。系统级操作只通过明确的 Tauri command 暴露给前端。

### 前端

Vue 3、TypeScript、Vite、Tailwind CSS 和 shadcn-vue 负责界面。主要页面：

- 生成：提示词、反向提示词、模型、尺寸、采样参数和生成数量。
- 任务：当前进度、状态和错误。
- 历史：结果缩略图、参数和输出位置。
- 设置：本地或远程模式、ComfyUI 目录、API 地址和连接测试。

### Local Agent

Python FastAPI 负责：

- 管理应用配置和任务记录。
- 查询 ComfyUI 的模型与系统状态。
- 将表单参数写入内置 ComfyUI API 工作流。
- 提交任务并通过 WebSocket 跟踪执行。
- 收集输出文件并向前端提供统一结果。

### ComfyUI

ComfyUI 是独立推理引擎。应用不修改其核心代码，也不要求用户打开节点界面。

## 运行模式

### 本地模式

用户选择 ComfyUI 目录。应用验证目录中存在启动入口，然后启动 ComfyUI，等待 API 就绪，再连接 Agent。

### 远程模式

用户填写 ComfyUI API 地址。应用只进行连接和任务提交，不访问远程主机的文件系统。

## 数据流

1. 前端向 Agent 请求状态和 checkpoint 列表。
2. 用户填写参数并提交任务。
3. Agent 复制内置工作流模板并替换参数。
4. Agent 向 ComfyUI `/prompt` 提交工作流。
5. Agent 监听 ComfyUI WebSocket 事件并更新任务状态。
6. 完成后，Agent通过 ComfyUI 的文件接口取得结果信息。
7. 前端展示结果，Agent保存历史元数据。

## 数据存储

应用数据保存在用户应用数据目录：

- `config.json`：连接模式、目录和 API 地址。
- `history.json`：任务参数、状态、时间和结果引用。
- `outputs/`：本地模式下收集的生成结果。

不在仓库中保存用户模型或生成图片。

## 错误处理

- ComfyUI 未安装或目录无效：设置页显示明确验证错误。
- API 不可达：保留配置并允许重新测试。
- checkpoint 不存在：阻止提交并刷新模型列表。
- 工作流执行失败：记录 ComfyUI 错误并在任务页展示。
- 应用关闭：已保存的任务历史保留；首版不承诺恢复运行中的任务。

## 界面原则

- 默认只展示常用参数，高级采样参数放入折叠区。
- 任何时刻都清楚显示 ComfyUI 是否可用。
- 生成操作、进度和结果位于同一主流程内。
- 不暴露节点、端口协议和工作流 JSON 等底层概念。

## 测试

- 前端组件与状态管理单元测试。
- Agent 配置、工作流参数替换和历史存储单元测试。
- 使用模拟 ComfyUI 服务进行 API 集成测试。
- Tauri 目录选择和进程启动进行 Windows 手动验收。
- 最终验证构建产物可在未安装开发工具的 Windows 环境启动。

## 验收标准

用户能够在设置页配置本地目录或远程 API，连接后选择 checkpoint，提交一次文生图任务，看到进度与结果，并能在重启应用后查看历史记录。
