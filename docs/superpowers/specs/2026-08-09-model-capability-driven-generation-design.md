# 模型能力驱动的生成流程设计

## 目标

让用户先选择创作任务，再由软件筛选兼容模型、展示必要输入并构建正确的 ComfyUI 工作流。用户不需要通过英文模型名称判断模型用途。

## 范围

本次支持五种创作类型：

- 文生图
- 图生图
- 文生视频
- 图生视频
- 视频生视频

保留现有“图片生成”和“视频生成”两个页面，不合并导航入口。

## 模型能力档案

每个可生成模型增加能力档案，包含：

- `capabilities`：支持的创作类型。
- `required_inputs`：参考图、参考视频等必需输入。
- `required_components`：VAE、文本编码器、运动模型等配套组件。
- `workflow_family`：对应的工作流构建器类型。
- 中文用途说明和推荐参数。

能力档案优先使用内置模型规则和模型库元数据生成。名称规则只用于辅助识别，不能作为唯一依据。

无法识别的模型标记为“能力待确认”，默认不允许直接生成。用户可以在模型管理页修正能力，结果保存在本地。导入工作流后，可根据节点信息补充模型能力档案。

## 页面交互

### 图片生成

页面顶部增加“文生图 / 图生图”选择：

- 文生图不显示参考图输入。
- 图生图显示并要求参考图。
- 模型列表只展示支持当前创作类型的模型。

### 视频生成

保留“文生视频 / 图生视频 / 视频生视频”选择：

- 文生视频不要求参考媒体。
- 图生视频显示并要求参考图。
- 视频生视频显示并要求参考视频。
- 模型列表只展示支持当前创作类型的模型。

### 模型选择与切换

- 模型选中后显示中文用途、支持能力、必需组件和推荐参数。
- 不兼容的 LoRA、VAE、ControlNet 和运动模型隐藏或禁用，并说明原因。
- 切换创作类型时，清除不兼容的模型和参考输入，避免旧状态误提交。
- 模型管理页增加“能力设置”，允许用户修正用途和能力。

## 请求与工作流

生成请求增加明确的创作类型字段，后端不得再通过参考文件是否存在反推生成方式。

五种创作类型分别由独立工作流构建器处理。工作流构建器只接收已通过能力校验的模型和输入，负责组装对应的 ComfyUI 节点图。

提交前依次校验：

1. 当前模型支持所选创作类型。
2. 参考图或参考视频是否齐全。
3. 必需的 VAE、文本编码器、运动模型等组件是否可用。
4. 所需 ComfyUI 节点是否存在。

校验失败时在当前表单显示中文原因；缺少模型或组件时提供跳转模型管理入口。

## 数据流

1. 用户选择图片或视频页面。
2. 用户选择具体创作类型。
3. 前端根据模型能力档案筛选模型。
4. 用户选择模型，界面加载对应输入项和推荐参数。
5. 前端完成基础必填校验并提交明确的创作类型。
6. 后端再次校验模型能力和组件。
7. 后端选择对应工作流构建器并提交至 ComfyUI。

## 错误处理

- 能力未知：提示用户先确认模型用途。
- 模型不兼容：清除选择并说明支持的创作类型。
- 缺少参考输入：在对应上传区域标红提示。
- 缺少组件或节点：列出具体名称并提供模型管理入口。
- 工作流执行错误：沿用 ComfyUI 错误同步机制，并转换为中文说明。

## 验证范围

只验证本次涉及的模块：

- 五种创作类型的模型筛选。
- 动态表单显示和必填校验。
- 模型能力档案的保存与读取。
- 五种工作流构建器。
- 不兼容模型、缺失输入和缺失组件的中文错误提示。
- 前后端创作类型与能力字段的接口一致性。

不执行无关模块的完整回归。

## 暂不包含

- 自动理解任意第三方工作流的全部语义。
- 在线训练或自动修改模型文件。
- 为所有未知模型自动生成百分百准确的能力档案。
- 合并图片生成和视频生成导航页面。
